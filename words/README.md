# 단어 목록 작성 가이드

라이어 게임의 제시어는 이 폴더의 **YAML 파일**로 관리합니다.
**파일 하나 = 카테고리 하나**이고, 단어를 추가하려면 해당 파일에 한 줄만 추가하면 됩니다.

- 형식 참고: [YAML 공식 사이트](https://yaml.org/), 파서 문서: [eemeli/yaml](https://eemeli.org/yaml/)
- 편집기 지원: VS Code에 [YAML 확장(Red Hat)](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml)을 설치하면
  파일 첫 줄의 `# yaml-language-server: $schema=./schema.json` 덕분에 **자동완성과 실시간 오류 표시**가 됩니다.

## 1. 파일 구조

```yaml
# yaml-language-server: $schema=./schema.json
name: 음식          # 필수: 화면에 보이는 카테고리 이름
icon: 🍜            # 선택: 이모지
description: 요리 이름   # 선택

groups:             # 소분류 → 단어 목록
  면 요리:
    - 짜장면: [자장면]   # 별칭이 있는 단어
    - 짬뽕
    - 칼국수
  분식:
    - 떡볶이
    - 김밥

words:              # 소분류 없는 단어 (선택, groups와 함께 써도 됨)
  - 비빔밥
```

| 키 | 필수 | 설명 |
|---|---|---|
| `name` | ✅ | 카테고리 표시 이름. 다른 파일과 겹치면 안 됩니다. |
| `icon` | | 이모지 하나 |
| `description` | | 설명 한 줄 |
| `groups` | `groups`나 `words` 중 하나 이상 | `소분류 이름: [단어 목록]` |
| `words` | | 소분류 없는 단어 목록 |

### 단어 한 줄 쓰는 법

| 쓰는 법 | 의미 |
|---|---|
| `- 짬뽕` | 별칭 없는 단어 |
| `- 짜장면: 자장면` | 별칭 1개 |
| `- 텔레비전: [TV, 티비, 텔레비젼]` | 별칭 여러 개 |

## 2. 파일 이름 규칙

- `words/<id>.yaml` 형식이며 `id`는 **영문 소문자·숫자·하이픈**만 씁니다 (예: `food.yaml`, `k-drama.yaml`).
  - 한글 파일 이름은 macOS와 Linux가 한글을 저장하는 방식(NFD/NFC)이 달라 Git에서 문제를 일으킬 수 있어 피합니다.
- `_`로 시작하는 파일(예: `_template.yaml`)은 게임에서 **무시**됩니다. 새 카테고리는 `_template.yaml`을 복사해 시작하세요.
- 파일은 반드시 **UTF-8**로 저장하세요. (Windows 메모장의 ANSI/CP949 저장은 오류로 처리됩니다.)

## 3. 별칭(alias) 정책 — 정답 판정에 직접 영향

라이어가 마지막에 제시어를 맞힐 때, **단어 자체 또는 별칭과 일치하면 자동으로 정답**입니다.
띄어쓰기·대소문자·문장부호·전각 문자는 자동으로 무시되므로 별칭으로 넣을 필요가 없습니다 (`아이스 크림` = `아이스크림`).
가벼운 오타(`초콜렛`/`초콜릿`, `떡뽁이`/`떡볶이`)도 유사도 판정이 처리합니다.

별칭으로 **넣어야 하는 것**
- 표기 변형·외래어 표기 차이 중 글자 차이가 큰 것: `포클레인: [포크레인, 굴착기]`, `호주: 오스트레일리아`
- 같은 대상을 가리키는 다른 이름(동의어): `스마트폰: [핸드폰, 휴대폰]`, `튀르키예: 터키`
- 영문 표기·약어: `텔레비전: [TV, 티비]`

별칭으로 **넣으면 안 되는 것**
- 상위어·하위어: `스파게티`의 별칭에 `파스타`를 넣지 않습니다 (파스타는 더 넓은 개념).
- 비슷하지만 다른 대상: `부엉이` ≠ `올빼미`, `숨바꼭질` ≠ `술래잡기`
- 같은 카테고리의 다른 단어: 검사기가 `ALIAS_CONFLICT` 오류로 막습니다.

사람(방장 판정·플레이어 투표)이 인정한 추측은 `data/judgements.jsonl`에 기록됩니다.
`npm run check:words -- --suggest data/judgements.jsonl`을 실행하면 별칭으로 추가할 만한 후보를 보여 줍니다.

## 4. 소분류(groups)를 나누는 기준

- **바보 모드**에서는 라이어에게 시민과 **같은 소분류**의 다른 단어를 우선 줍니다.
  예: 시민 `짜장면` → 라이어 `짬뽕` (같은 `면 요리`). 비슷할수록 라이어가 들킬 때까지 시간이 걸려 재미있습니다.
- 소분류에 단어가 1개뿐이면 바보 모드에서 카테고리 전체에서 고릅니다 (검사기가 `SMALL_GROUP` 경고).
- 소분류는 3개 이상의 단어를 권장합니다.

## 5. YAML 주의사항

- 값은 모두 **문자열**로 읽습니다. `no`, `yes`, `1987` 같은 값도 그대로 단어가 됩니다(따옴표 불필요).
- 아래 문자가 **포함되거나 맨 앞에 오면** 따옴표로 감싸세요:
  `:` (콜론+공백), `#` (공백 뒤), 맨 앞의 `@ * & ! ? | > % [ ] { } , '"`
  - 예: `- "C#"`, `- "?!"`
- 들여쓰기는 **공백**으로 합니다(탭 금지). 같은 목록의 항목은 같은 칸에 맞춥니다.
- 같은 소분류 이름을 두 번 쓰면 오류(`DUPLICATE_KEY`)입니다.

## 6. 중복·오류 검사

```bash
npm run check:words
```

| 코드 | 수준 | 의미 |
|---|---|---|
| `DUP_WORD` | 오류 | 같은 카테고리에 같은 단어가 두 번 (띄어쓰기 등 무시하고 비교, 소분류가 달라도) |
| `ALIAS_CONFLICT` | 오류 | 별칭이 같은 카테고리의 다른 단어·별칭과 겹침 |
| `ALIAS_SAME_AS_WORD` | 경고 | 별칭이 단어 자신과 같음 (불필요) |
| `TOO_FEW_WORDS` | 오류(2개 미만) / 경고(10개 미만) | 단어 수 부족 |
| `SMALL_GROUP` | 경고 | 단어가 1개뿐인 소분류 |
| `CROSS_CATEGORY_DUP` | 경고 (`--strict`면 오류) | 다른 카테고리에도 있는 단어 (예: `배` = 과일/교통수단) |
| `SIMILAR_WORDS` | 정보 (`--similar`일 때만) | 오타로 의심되는 매우 비슷한 단어 쌍 |
| `YAML_SYNTAX`, `DUPLICATE_KEY`, `NO_NAME`, `BAD_ENTRY`, `EMPTY_WORD`, `UNKNOWN_FIELD`, `BAD_ENCODING`, `DUP_CATEGORY_NAME` | 오류 | 파일 형식 오류 |
| `EMPTY_ALIAS`, `ODD_CHARS` | 경고 | 빈 별칭, 특이한 문자 |

옵션:

```bash
npm run check:words -- --strict                 # 카테고리 간 중복도 오류로 처리
npm run check:words -- --similar                # 유사 단어 쌍 표시 (기본 기준 0.85)
npm run check:words -- --similar=0.8            # 기준 변경
npm run check:words -- --suggest data/judgements.jsonl   # 사람이 인정한 추측 → 별칭 후보
npm run check:words -- --dir 다른/폴더           # 다른 폴더 검사
```

오류가 하나라도 있으면 종료 코드 1로 끝나므로 CI(GitHub Actions)에서 자동으로 걸러집니다.
서버는 시작할 때도 같은 검사를 실행하며, 오류가 있는 항목만 빼고 게임을 진행합니다(로그에 표시).

단어 파일을 수정한 뒤에는 **서버를 재시작**해야 반영됩니다. (`npm run dev`로 실행 중이면 자동 재시작)
